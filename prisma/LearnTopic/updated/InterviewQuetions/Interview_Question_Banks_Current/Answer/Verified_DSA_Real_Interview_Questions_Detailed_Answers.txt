1.  [REPEATED] Reverse a singly linked list. Reported by: Amazon SDE1;
    Microsoft SDE; Samsung Bangalore; other reports. Evidence: Amazon
    explicitly reported “Reverse a linked list”; Microsoft reported the
    same problem; Samsung reported reverse a linked list. Sources: -
    LeetCode Microsoft SDE interview experience - LeetCode Amazon SDE1
    onsite experience - GeeksforGeeks Samsung Bangalore internship
    experience

Answer: Use three pointers—prev, current, and next—to reverse the links
one node at a time. Save current.next before changing it, point
current.next to prev, then advance prev and current. This gives O(n)
time and O(1) auxiliary space. The important edge cases are an empty
list and a single-node list.

Example: Input: 1 -> 2 -> 3 -> 4 -> null Output: 4 -> 3 -> 2 -> 1 ->
null

C++: ListNode* reverse(ListNode* head) { ListNode* prev = nullptr;
ListNode* cur = head; while (cur) { ListNode* next = cur->next;
cur->next = prev; prev = cur; cur = next; } return prev; }

repeated independent reports. In the interview, explain the approach
before writing code and state complexity clearly.

Handle null, one-node, and boundary cases. • State time and
auxiliary-space complexity.

2.  [REPORTED] Reverse a linked list in groups of a given size. Reported
    by: Amazon SDE1; GeeksforGeeks SDE interview. Source: -
    GeeksforGeeks Amazon SDE-1 interview experience - GeeksforGeeks SDE
    Android Team interview experience

Answer: Process the list group by group. For each complete group of k
nodes, reverse its links and connect the previous group’s tail to the
new head. Decide explicitly what to do with a final group smaller than
k; the common variant leaves it unchanged. The iterative approach is
O(n) time and O(1) auxiliary space.

7.  [REPORTED] Solve linked-list coding questions with linear time
    complexity. Reported by: GeeksforGeeks SDE interview experience.
    Source: GeeksforGeeks SDE Android Team interview experience.
    ==================================================== 2. LRU CACHE /
    HASHING ====================================================

Answer: The key is to avoid repeated scans of the list. Maintain the
necessary state while traversing each node once. Typical linked-list
operations such as reversal, cycle detection, or midpoint detection can
be solved in O(n). Explain why no node is processed a superlinear number
of times.

Example: C++ design: class LRUCache { int cap; list<pair<int,int>> dq;
// front = most recently used unordered_map<int,
list<pair<int,int>>::iterator> pos; public: int get(int key) { auto it =
pos.find(key); if (it == pos.end()) return -1; int value =
it->second->second; dq.splice(dq.begin(), dq, it->second); return value;
}

    void put(int key, int value) {
        if (auto it = pos.find(key); it != pos.end()) {
            it->second->second = value;
            dq.splice(dq.begin(), dq, it->second);
            return;
        }
        dq.push_front({key, value});
        pos[key] = dq.begin();
        if ((int)dq.size() > cap) {
            auto last = prev(dq.end());
            pos.erase(last->first);
            dq.pop_back();
        }
    }

};

8.  [REPEATED] Implement an LRU cache. Reported by: Amazon, Microsoft,
    Joveo, OnlineSales AI, Flipkart, OLX Groups and other interview
    experiences. Sources: - LeetCode Amazon SDE1 onsite - LeetCode
    Microsoft SDE - LeetCode Joveo SDE1 - LeetCode OnlineSales AI SDE2 -
    GeeksforGeeks Flipkart SDE II - GeeksforGeeks OLX Groups

Answer: An LRU cache needs O(1) average-time lookup, insertion, and
eviction. The standard design combines a hash map from key to a node
with a doubly linked list ordered from most recently used to least
recently used. get() moves a found node to the front; put() updates an
existing node or inserts a new one at the front, and when capacity is
exceeded removes the tail. Hash-map lookup and constant-time list
unlink/insert give O(1) average time.

Example: C++ design: class LRUCache { int cap; list<pair<int,int>> dq;
// front = most recently used unordered_map<int,
list<pair<int,int>>::iterator> pos; public: int get(int key) { auto it =
pos.find(key); if (it == pos.end()) return -1; int value =
it->second->second; dq.splice(dq.begin(), dq, it->second); return value;
}

    void put(int key, int value) {
        if (auto it = pos.find(key); it != pos.end()) {
            it->second->second = value;
            dq.splice(dq.begin(), dq, it->second);
            return;
        }
        dq.push_front({key, value});
        pos[key] = dq.begin();
        if ((int)dq.size() > cap) {
            auto last = prev(dq.end());
            pos.erase(last->first);
            dq.pop_back();
        }
    }

};

58. [REPEATED] Implement an LRU cache.

Answer: An LRU cache needs O(1) average-time lookup, insertion, and
eviction. The standard design combines a hash map from key to a node
with a doubly linked list ordered from most recently used to least
recently used. get() moves a found node to the front; put() updates an
existing node or inserts a new one at the front, and when capacity is
exceeded removes the tail. Hash-map lookup and constant-time list
unlink/insert give O(1) average time.

Example: C++ design: class LRUCache { int cap; list<pair<int,int>> dq;
// front = most recently used unordered_map<int,
list<pair<int,int>>::iterator> pos; public: int get(int key) { auto it =
pos.find(key); if (it == pos.end()) return -1; int value =
it->second->second; dq.splice(dq.begin(), dq, it->second); return value;
}

    void put(int key, int value) {
        if (auto it = pos.find(key); it != pos.end()) {
            it->second->second = value;
            dq.splice(dq.begin(), dq, it->second);
            return;
        }
        dq.push_front({key, value});
        pos[key] = dq.begin();
        if ((int)dq.size() > cap) {
            auto last = prev(dq.end());
            pos.erase(last->first);
            dq.pop_back();
        }
    }

};
