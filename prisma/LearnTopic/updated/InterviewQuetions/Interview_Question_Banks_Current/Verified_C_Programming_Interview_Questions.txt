C INTERVIEW QUESTIONS — VERIFIED INTERVIEW-EXPERIENCE-BASED SET

Purpose

This is a smaller, higher-confidence C interview bank built from
questions and topics explicitly reported in published
interview-experience reports and widely recurring C interview question
sets.

Important: - These are NOT presented as questions asked at every
company. - Where an interview report explicitly described a
question/task, the question is marked [REPORTED]. - Some wording is
lightly normalized for clarity rather than copied verbatim. - Questions
marked [COMMON] are recurring interview questions supported by multiple
interview-preparation sources, but are not claimed to be tied to one
specific interview. - No company-specific guarantee is implied.

INTERVIEW FOLLOW-UPS
============================================================

161. [FOLLOW-UP] You said malloc() returns heap memory. What do you do
     if the allocation fails?

     that still points to the same memory?

     aliases pointing to the same memory?

     arr[i] work through pointer arithmetic?

     a function?
166. [FOLLOW-UP] You said int is 4 bytes. Is that guaranteed by C?
167. [FOLLOW-UP] You said volatile prevents optimization. Does it make
     counter++ atomic?
168. [FOLLOW-UP] You said the code is thread-safe. Where exactly is the
     synchronization?
169. [FOLLOW-UP] You used a mutex. What prevents two threads from
     acquiring locks in opposite order?
170. [FOLLOW-UP] You used strncpy(). How do you guarantee null
     termination?
171. [FOLLOW-UP] You used memcpy(). What happens if source and
     destination overlap?
172. [FOLLOW-UP] You returned a pointer from a function. Who owns that
     memory?
173. [FOLLOW-UP] You allocated memory inside a function. Who is
     responsible for freeing it?
174. [FOLLOW-UP] You returned the address of a local variable. What
     happens after the function returns?
175. [FOLLOW-UP] You used a static local variable. What happens when the
     function is called again?
176. [FOLLOW-UP] You used a global variable. What problems could that
     introduce in a multithreaded program?
177. [FOLLOW-UP] You used a union to save memory. How do you know which
     member is currently valid?
178. [FOLLOW-UP] You serialized a structure directly to disk. Will the
     same bytes necessarily work on another architecture?
179. [FOLLOW-UP] Your program works without optimization but fails with
     -O2. What classes of bugs would you investigate?
180. [FOLLOW-UP] The crash occurs in free(). Does that necessarily mean
     free() is the bug?

     whether memory corruption happened earlier?

     leak originates?
183. [FOLLOW-UP] A pointer looks valid in the debugger but dereferencing
     it crashes. What would you investigate?
184. [FOLLOW-UP] You added a print statement and the crash disappeared.
     What might that indicate?
185. [FOLLOW-UP] You added more threads and performance became worse.

186. [FOLLOW-UP] You used dynamic allocation for every small object.

189. [FOLLOW-UP] You need to access a hardware register. Why might
     volatile be required?
190. [FOLLOW-UP] You need to share data between an ISR and normal code.
     What synchronization issues do you consider?
