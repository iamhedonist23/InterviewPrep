1.  [SOURCE QUESTION] Question : What is the difference between
    Artificial Intelligence, Machine Learning, and Deep Learning?

Answer : Artificial Intelligence (AI) is the broad field of building
systems that perform tasks requiring capabilities associated with human
intelligence, such as reasoning, perception, planning, language
understanding, or decision-making. Machine Learning (ML) is a subset of
AI in which models learn patterns from data rather than being explicitly
programmed with every rule. Deep Learning is a subset of ML that uses
multi-layer neural networks to learn increasingly complex
representations.

The relationship is therefore AI ⟶ ML ⟶ Deep Learning. Not every AI
system uses machine learning, and not every machine-learning system uses
deep learning.

A useful interview distinction is that AI describes the overall
goal/capability, ML describes a data-driven learning approach, and deep
learning describes a particular family of ML techniques based primarily
on neural networks.

customer questions. The engineer first defines the target metric and
constraints, builds a small representative evaluation set, implements a

2.  [SOURCE QUESTION] Question : What is the difference between
    supervised and unsupervised learning?

Answer : Supervised learning trains a model using labeled examples,
where each training record contains input features and a target value.
The model learns a mapping from inputs to targets and is commonly used
for classification and regression.

Unsupervised learning works without a target label. The model attempts
to discover structure in the data, such as clusters, latent
representations, or unusual observations. Clustering and
dimensionality-reduction methods are common examples.

The practical difference is whether the learning objective has an
explicitly provided target. In a production project, the choice depends
on what data is available and what business outcome is required.

3.  [SOURCE QUESTION] Question : What is overfitting, and how would you
    reduce it?

Answer : Overfitting occurs when a model learns the training data too
specifically, including noise or accidental patterns, so training
performance is strong but performance on unseen data is poor. A large
train-test gap is a common warning sign.

Ways to reduce overfitting include using more representative training
data, regularization, simpler models, feature selection, early stopping,
dropout for neural networks, data augmentation where appropriate, and
cross-validation for model selection. For tree models, limiting depth or
requiring a minimum number of samples per split can help.

The important interview point is that the solution should match the
cause; simply choosing a more complex model can make overfitting worse.

Example : Example: A decision tree reaches 99% training accuracy but
only 72% validation accuracy. The team tests shallower trees with
cross-validation and finds that a depth-limited model gives 86%
validation accuracy, indicating better generalization.

Interview Tip : Give a direct definition first, then explain the
mechanism, trade-offs, and one practical example. Avoid listing
buzzwords without explaining why you would choose them.

4.  [SOURCE QUESTION] Question : What is underfitting, and how would you
    address it?

Answer : Underfitting happens when the model is too simple or
insufficiently trained to capture the important relationship between
inputs and the target. It usually produces poor performance on both
training and validation/test data.

Typical remedies are increasing model capacity, adding useful features,
reducing excessive regularization, training longer when appropriate, and
improving the representation of the problem. The goal is not maximum
complexity; it is enough capacity to capture meaningful patterns without
losing generalization.

A good diagnosis compares training and validation performance rather
than labeling a model underfit from validation accuracy alone.

Example : Example: A decision tree reaches 99% training accuracy but

5.  [SOURCE QUESTION] Question : What is a confusion matrix?

Answer : A confusion matrix summarizes classification predictions by
comparing actual classes with predicted classes. For binary
classification it contains true positives (TP), true negatives (TN),
false positives (FP), and false negatives (FN).

These four counts support metrics such as accuracy, precision, recall,
specificity, and F1 score. The matrix is especially useful when accuracy
hides an important error type—for example, when false negatives are much
more costly than false positives.

For multiclass classification, the matrix expands to one row/column per
class and shows which classes are being confused with one another.

Example : Example: For fraud detection, 100 transactions are evaluated:
8 are truly fraudulent. If the model flags 10 transactions and 6 are
truly fraud, then precision is 6/10 = 60% and recall is 6/8 = 75%. The
confusion matrix records these outcomes so the team can decide whether
false positives or missed fraud is the more important business cost.

6.  [SOURCE QUESTION] Question : What is the difference between
    precision and recall?

Answer : Precision answers: among the examples the model predicted as
positive, how many were actually positive? Precision = TP / (TP + FP).

Recall answers: among all actual positive examples, how many did the
model successfully identify? Recall = TP / (TP + FN).

High precision is important when false positives are expensive, while
high recall is important when missing a positive case is expensive. They
often trade off as the decision threshold changes, so the right target
depends on the application.

Example : Example: For fraud detection, 100 transactions are evaluated:
8 are truly fraudulent. If the model flags 10 transactions and 6 are
truly fraud, then precision is 6/10 = 60% and recall is 6/8 = 75%. The
confusion matrix records these outcomes so the team can decide whether
false positives or missed fraud is the more important business cost.

mechanism, trade-offs, and one practical example. Avoid listing

7.  [SOURCE QUESTION] Question : What is the difference between
    precision and accuracy?

Answer : Accuracy is the fraction of all predictions that are correct:
(TP + TN) / total predictions. Precision is the fraction of predicted
positives that are actually positive: TP / (TP + FP).

Accuracy can be misleading with imbalanced classes. For example, if only
1% of transactions are fraudulent, a model that predicts every
transaction as legitimate can achieve about 99% accuracy while detecting
no fraud. Precision, recall, PR-AUC, or cost-based metrics may be more
informative depending on the objective.

8.  [SOURCE QUESTION] Question : What is the difference between
    classification and regression?

Answer : Classification predicts a discrete category, such as fraud
versus legitimate or one of several product classes. Regression predicts
a continuous numerical value, such as demand, revenue, or delivery time.

The distinction is based on the target variable and loss/evaluation
approach, not simply on the algorithm name. Some algorithms have both
classification and regression variants.

Examples of classification metrics include precision, recall, F1,
ROC-AUC, and accuracy; regression commonly uses MAE, MSE/RMSE, or R²,
chosen according to the business objective and error costs.

9.  [SOURCE QUESTION] Question : What is the difference between training
    data, validation data and test data?

Answer : Training data is used to fit model parameters. Validation data
is used during development to choose models, hyperparameters,
thresholds, or other decisions. Test data is held back until the end to
estimate performance on unseen data.

The key principle is avoiding test-set leakage. If the test set
influences model selection, it is no longer an unbiased final evaluation
set.

For small datasets, cross-validation can provide more stable
model-selection estimates, while a final untouched test set can still be
retained when enough data is available.

10. [SOURCE QUESTION] Question : What is cross-validation and why is it
    useful?

Answer : Cross-validation repeatedly splits the available development
data into training and validation portions so that performance is
evaluated across multiple splits. In k-fold cross-validation, the data
is divided into k folds and each fold serves as validation once.

It reduces dependence on one arbitrary split and is useful for model
comparison and hyperparameter selection, especially with limited data.
For time-dependent data, ordinary random folds can leak future
information, so time-aware validation should be used instead. Grouped
data may also require group-aware splitting.

Example : Example: A decision tree reaches 99% training accuracy but
only 72% validation accuracy. The team tests shallower trees with
cross-validation and finds that a depth-limited model gives 86%
validation accuracy, indicating better generalization.

11. [SOURCE QUESTION] Question : What is the bias-variance trade-off?

Answer : Bias describes error from overly restrictive assumptions in the
model; variance describes sensitivity to the particular training sample.
High bias is commonly associated with underfitting, while high variance
is commonly associated with overfitting.

Increasing model complexity can reduce bias but increase variance.
Regularization, more data, feature engineering, and appropriate model
selection can shift this balance.

In an interview, emphasize that the goal is not to minimize bias or
variance independently. The practical goal is low generalization error
on the target distribution.

Example : Example: A decision tree reaches 99% training accuracy but
only 72% validation accuracy. The team tests shallower trees with
cross-validation and finds that a depth-limited model gives 86%
validation accuracy, indicating better generalization.

12. [SOURCE QUESTION] Question : What is an embedding?

Answer : An embedding is a learned numerical representation of an
object—such as text, an image, a user, or a product—mapped into a vector
space where useful relationships can be measured geometrically.

For text, semantically related passages can receive vectors that are
close under an appropriate similarity measure. Embeddings are widely
used for semantic search, recommendation, clustering, retrieval, and
retrieval-augmented generation.

An embedding is not simply a list of human-readable features; it is a
learned representation whose dimensions generally do not have
individually interpretable meanings.

Example : Example: Store an embedding for “wireless noise-cancelling
headphones” and compare it with the embedding for “Bluetooth headphones
with active noise reduction.” A semantic retrieval system can recognize
their related meaning even though the wording differs.

13. [SOURCE QUESTION] Question : What is a vector database?

Answer : A vector database stores and retrieves high-dimensional vectors
efficiently, usually using an approximate nearest-neighbor index rather
than scanning every vector for every query. It commonly stores metadata
alongside vectors so retrieval can be filtered by tenant, document type,
permissions, date, or other constraints.

In an AI application, a typical flow is: generate an embedding for a
query, retrieve similar stored vectors, apply metadata filtering or
reranking if needed, and pass the best evidence to the downstream model.

The database is an infrastructure component; it does not automatically
guarantee semantic quality. Embedding quality, chunking, indexing,
filtering, and evaluation still matter.

Example : Example: Store an embedding for “wireless noise-cancelling
headphones” and compare it with the embedding for “Bluetooth headphones
with active noise reduction.” A semantic retrieval system can recognize
their related meaning even though the wording differs.

14. [SOURCE QUESTION] Question : How does cosine similarity work?

Answer : Cosine similarity measures the angle between two vectors rather
than their raw magnitude. It is commonly defined as dot(A,B) / (||A||
||B||). Values closer to 1 indicate vectors pointing in similar
directions, while values near 0 indicate little directional similarity
for typical nonnegative/text embedding use cases.

It is useful for embeddings because vector magnitude may be less
important than the direction of the learned representation.

In production retrieval, the exact metric should match the embedding
model and index configuration; cosine similarity, dot product, and
Euclidean distance are not interchangeable without considering
normalization.

Example : Example: Store an embedding for “wireless noise-cancelling
headphones” and compare it with the embedding for “Bluetooth headphones
with active noise reduction.” A semantic retrieval system can recognize
their related meaning even though the wording differs.

15. [REPORTED] Question : What is RAG and how does it work?

Answer : Retrieval-Augmented Generation (RAG) combines information
retrieval with generation. Instead of asking an LLM to answer only from
its parameters, the application first retrieves relevant external
content and then supplies that evidence to the model as context.

A typical RAG flow is: ingest documents → clean and chunk them →
generate embeddings → index chunks → embed the user query → retrieve
candidates → optionally rerank/filter them → build a grounded prompt →
generate an answer → evaluate the result.

RAG can improve freshness and grounding without retraining the model for
every document update, but it can still fail when retrieval is poor,
context is noisy, permissions are wrong, or the model ignores or
misinterprets evidence.

Example : Example: A support assistant receives “What is the refund
window for an annual plan?” The system retrieves the current
billing-policy section, filters it to documents the customer can access,
and supplies that evidence to the LLM. The answer cites the retrieved
policy instead of relying only on the model’s memorized knowledge.

Interview Tip : Treat this as a higher-confidence reported interview
question, but do not describe it as guaranteed or universal. Explain the
design/answer from first principles and be ready for follow-up
trade-offs.

and whether the candidate can connect model behavior to a practical

Key Points to Remember : RAG quality depends on ingestion, chunking,
embeddings, retrieval, filtering, reranking, context construction,
generation, and evaluation.

Common Follow-up Questions : - How would you measure retrieval quality

16. [SOURCE QUESTION] Question : What is the difference between prompt
    engineering and fine-tuning?

Answer : Prompt engineering changes the instructions, examples, context,
output format, or other input supplied to a model while leaving model
weights unchanged. It is usually fast to iterate and works well when the
desired behavior can be expressed through instructions and retrieved
context.

Fine-tuning updates model parameters using task-specific training data.
It can improve consistency, style, or specialized behavior when
prompting alone is insufficient and sufficient high-quality examples
exist.

A practical decision starts with the cheapest reliable intervention:
improve prompting/context and evaluation first, then consider
fine-tuning when a stable behavioral gap remains. RAG is often
preferable when the missing information is changing external knowledge
rather than behavior.

Example : Example: A company evaluates a base model with a carefully
designed prompt on 1,000 labeled support queries. It then evaluates a
LoRA-adapted version on the same held-out set. If the adapted model
improves the target metric enough to justify training and hosting costs,
the team can adopt it.

17. [SOURCE QUESTION] Question : What is hallucination in an LLM?

Answer : An LLM hallucination is an output that presents unsupported,
fabricated, or factually incorrect information as though it were
reliable. It can include invented citations, incorrect details, or
confident answers when the model lacks adequate evidence.

Hallucinations occur because language models optimize for generating
plausible continuations rather than guaranteeing factual truth.
Retrieval quality, model behavior, prompt design, temperature, tool use,
and the task itself can affect the risk.

A production system should treat factuality as an evaluated property,
not assume that a confident-sounding response is correct.

Example : Example: Suppose an online support application must answer
customer questions. The engineer first defines the target metric and
constraints, builds a small representative evaluation set, implements a
simple baseline, measures its failure modes, and then adds complexity
only where the measured failures justify it.

19. [SOURCE QUESTION] Question : What are tokens and why do they matter
    for LLM applications?

Answer : Tokens are the units into which an LLM tokenizer divides input
and output text. A token may represent a whole word, part of a word,
punctuation, or another text fragment depending on the tokenizer.

Tokens matter because they determine context-window usage, latency, and
often API cost. Long prompts consume more input tokens, and long
generated responses consume more output tokens.

AI engineers therefore pay attention to prompt size, retrieved-context
size, output limits, tokenization behavior for the target languages, and
truncation policies.

20. [SOURCE QUESTION] Question : What is a context window?

Answer : A context window is the maximum amount of tokenized information
a model can process as context for a request, subject to the model’s
specific limits. It can include system instructions, conversation
history, retrieved documents, tool results, and the requested output
depending on the API/model behavior.

A larger context window does not automatically mean better answers.
Excessive or low-quality context can increase cost, latency, and
distraction. Good AI systems therefore retrieve and compress relevant
information instead of blindly placing every available document into the
prompt.

21. [SOURCE QUESTION] Question : What do temperature and top-p control?

Answer : Temperature controls how sharply or broadly the model samples
from its next-token probability distribution. Lower temperature
generally makes output more deterministic; higher temperature generally
increases variability.

Top-p, or nucleus sampling, restricts sampling to the smallest set of
tokens whose cumulative probability reaches a chosen threshold. Lower
top-p narrows the candidate set.

They are sampling controls, not direct “intelligence” controls. For
deterministic business workflows, low randomness is often preferred; for
creative generation, more variability may be useful. The exact effect
depends on the model and serving implementation.

23. [REPORTED] Question : Explain how RAG works.

Answer : Retrieval-Augmented Generation (RAG) combines information
retrieval with generation. Instead of asking an LLM to answer only from
its parameters, the application first retrieves relevant external
content and then supplies that evidence to the model as context.

A typical RAG flow is: ingest documents → clean and chunk them →
generate embeddings → index chunks → embed the user query → retrieve
candidates → optionally rerank/filter them → build a grounded prompt →
generate an answer → evaluate the result.

RAG can improve freshness and grounding without retraining the model for
every document update, but it can still fail when retrieval is poor,
context is noisy, permissions are wrong, or the model ignores or
misinterprets evidence.

Example : Example: A support assistant receives “What is the refund
window for an annual plan?” The system retrieves the current
billing-policy section, filters it to documents the customer can access,
and supplies that evidence to the LLM. The answer cites the retrieved
policy instead of relying only on the model’s memorized knowledge.

26. [SOURCE QUESTION] Question : How would you choose a chunking
    strategy for a RAG system?

Answer : Chunking divides source documents into retrievable units. A
good strategy balances semantic completeness against retrieval precision
and context cost.

Start with document-aware boundaries such as headings, paragraphs,
sections, tables, or code blocks rather than blindly cutting every N
characters. Use overlap only when it helps preserve cross-boundary
context. Chunk size should be evaluated against the document type,
embedding model, query style, and downstream context budget.

For long structured documents, hierarchical or parent-child retrieval
can preserve section context while keeping retrieved units focused.
Always evaluate retrieval recall and answer quality on representative
queries.

28. [SOURCE QUESTION] Question : When would you use vector search versus
    hybrid search?

Answer : Vector search retrieves by semantic similarity, which is strong
when the query and relevant content use different but related wording.
Lexical search, such as BM25, is strong for exact terms, identifiers,
product codes, names, and rare keywords.

Hybrid search combines both signals and often works better for
enterprise or e-commerce corpora containing both natural language and
exact-match requirements. A common design retrieves candidates from both
systems and combines or reranks them.

The choice should be driven by evaluation on real queries, including
exact-match and semantic cases.

30. [SOURCE QUESTION] Question : What is reranking in a RAG pipeline?

Answer : Reranking is a second-stage retrieval step that takes an
initial candidate set and reorders it using a more expensive relevance
model, commonly a cross-encoder or specialized reranker.

The first-stage retriever is optimized for speed and recall; the
reranker is optimized for finer relevance discrimination. This
architecture allows the system to search many candidates cheaply and
spend more computation only on a smaller set.

Reranking is especially useful when the initial top results contain
several semantically related but not actually relevant chunks.

34. [SOURCE QUESTION] Question : How would you choose between prompt
    engineering and fine-tuning?

Answer : Prompt engineering changes the instructions, examples, context,
output format, or other input supplied to a model while leaving model
weights unchanged. It is usually fast to iterate and works well when the
desired behavior can be expressed through instructions and retrieved
context.

Fine-tuning updates model parameters using task-specific training data.
It can improve consistency, style, or specialized behavior when
prompting alone is insufficient and sufficient high-quality examples
exist.

A practical decision starts with the cheapest reliable intervention:
improve prompting/context and evaluation first, then consider
fine-tuning when a stable behavioral gap remains. RAG is often
preferable when the missing information is changing external knowledge
rather than behavior.

Example : Example: A company evaluates a base model with a carefully
designed prompt on 1,000 labeled support queries. It then evaluates a
LoRA-adapted version on the same held-out set. If the adapted model
improves the target metric enough to justify training and hosting costs,
the team can adopt it.

mechanism, trade-offs, and one practical example. Avoid listing

clarification, trade-off analysis, scalability, reliability, security,

35. [SOURCE QUESTION] Question : When would you use LoRA or QLoRA
    instead of full fine-tuning?

Answer : LoRA, or Low-Rank Adaptation, trains a relatively small set of
low-rank adapter parameters while keeping most base-model weights
frozen. It can substantially reduce trainable parameters and memory
requirements compared with full fine-tuning.

training LoRA adapters, reducing memory usage further and making
fine-tuning larger models more accessible on limited hardware.

Use these approaches when task-specific adaptation is needed but full
fine-tuning is unnecessarily expensive. Evaluate whether adapter-based
training provides the required quality, stability, and deployment
characteristics.

51. [SOURCE QUESTION] Question : How would you reduce latency in an AI

58. [SOURCE QUESTION] Question : Choose between a large general model, a
    fine-tuned open model and a distilled model for a classification
    task. How would you justify the trade-offs?

Answer : Choose based on the task’s required quality, latency, cost,
privacy, and operational constraints. A large general model may provide
the strongest baseline quality and flexibility but can be slower and
more expensive. A fine-tuned open model can provide specialized behavior
and deployment control, but introduces training, evaluation, hosting,
and maintenance costs. A distilled model can reduce latency and cost
substantially when its quality is sufficient for the task.

For a classification problem, compare them on a fixed labeled test set
using task-appropriate metrics, calibration, latency, throughput,
memory, and total cost of ownership. The final decision should be
evidence-based rather than assuming model size determines quality.

Example : Example: For fraud detection, 100 transactions are evaluated:
8 are truly fraudulent. If the model flags 10 transactions and 6 are
truly fraud, then precision is 6/10 = 60% and recall is 6/8 = 75%. The
confusion matrix records these outcomes so the team can decide whether
false positives or missed fraud is the more important business cost.
