1.  [REPORTED] Question: Explain pointers in C and how they work.

Answer: A pointer is an object that stores the address of another object
or function (for function pointers). It supports indirect access and is
central to arrays, dynamic memory, linked lists, callbacks, and systems
programming. A pointer can be null and can become dangling when the
pointed object’s lifetime ends. Pointer arithmetic is defined within an
appropriate array object and scales by the pointed-to type size.

Example: int value = 10; int p = &value; printf(“%d”, p); // prints 10

Interview Tip: Give the direct answer first, then explain the mechanism
and one practical example. For coding questions, state time/space
complexity and discuss edge cases. For debugging questions, explain how
you would reproduce, isolate, diagnose, fix, and verify the problem.

What Interviewer Is Testing: C language fundamentals, pointers and
memory safety, undefined behavior awareness, problem-solving ability,
debugging skill, and practical systems-level reasoning.

Key Points to Remember: Be precise about object lifetime, allocation
ownership, array/pointer differences, integer/type rules,
synchronization, and what the C standard actually guarantees. Do not
present compiler-specific behavior as portable C behavior.

Common Follow-up Questions: What happens internally? What is the edge
case? What is the time/space complexity? What happens on allocation
failure? Is the behavior defined by the C standard? How would you debug
it in production?

Common Mistakes: Confusing arrays with pointers, forgetting the
terminating ‘\0’, dereferencing invalid pointers, ignoring allocation
failure, using unsafe string operations, assuming sizeof is a runtime
string length, or claiming volatile provides atomicity/thread safety.

3.  [REPORTED] Question: What is malloc()?

Answer: malloc allocates a requested number of bytes of uninitialized
storage and returns a pointer to that storage, or NULL if allocation
fails. The returned storage has suitable alignment for objects that
require fundamental alignment. The caller is responsible for checking
failure and eventually calling free() when the storage is no longer
needed.

Example: int p = malloc(10 sizeof p); if (p) { / use p */ } free(p);

4.  [REPORTED] Question: What is calloc()?

Answer: calloc allocates space for an array of elements and initializes
all allocated bytes to zero. It returns NULL on failure. The zeroed
bytes are useful for many data structures, but ‘all-bits-zero’ is not a
universal statement that every possible C type has the numerical value
zero.

Example: int p = calloc(10, sizeof p); if (p) { /* elements start with
zeroed bytes */ } free(p);

13. [REPORTED] Question: Write a program to reverse a linked list.

Answer: A linked list is a sequence of nodes connected through pointers.
A singly linked list stores a value and a pointer to the next node. It
supports efficient insertion/removal when the relevant node/link is
already known, but random indexing is O(n).

Example: Node prev = NULL, cur = head; while (cur) { Node *next =
cur->next; cur->next = prev; prev = cur; cur = next; } head = prev;

19. [REPORTED] Question: Solve a bitmask/bitwise manipulation problem.

Answer: Use bitwise operators intentionally: & tests/masks bits, | sets
selected bits, ^ toggles bits, and ~ complements bits. To set bit k use
x |= (1u << k); to clear use x &= ~(1u << k); to toggle use x ^= (1u <<
k); to test use (x & (1u << k)) != 0. Use unsigned types for predictable
bitwise reasoning.

Example: unsigned x = 0; x |= (1u<<3); x &= ~(1u<<3); x ^= (1u<<3);

20. [REPORTED] Question: Write a Fibonacci program.

Answer: The iterative solution keeps the previous two Fibonacci values
and runs in O(n) time and O(1) space. Naive recursion has exponential
time because it repeatedly recomputes the same subproblems; memoization
can reduce it to O(n).

Example: unsigned long long a=0,b=1; for (int i=0;i<n;i++){ unsigned
long long t=a+b; a=b; b=t; }

and the original allocation remains valid. This is why assigning realloc
directly to the only pointer can lose the original address.

62. [COMMON] Question: What is double-free?

Answer: Double-free means passing the same allocated block to free()
more than once without a new valid allocation in between. It is
undefined behavior and can corrupt the allocator. Ownership should be
unambiguous and a resource should have exactly one appropriate release
operation.

    memory?

objects are commonly stored in stack frames and have
scope/lifetime-based cleanup; dynamically allocated storage comes from
the heap/free store and remains until explicitly released or an owning
abstraction releases it. The C standard does not mandate a particular
physical stack/heap layout.

81. [COMMON] Question: What does volatile mean?

Answer: volatile tells the implementation that accesses to the object
are observable and should not be optimized away or merged in ways that
violate the language’s volatile-access rules. It is useful for
memory-mapped hardware and some signal/ISR scenarios. It does not make
compound operations atomic and does not by itself provide thread
synchronization.

Example: volatile unsigned status; while ((status & READY_BIT) == 0) {

102. [COMMON] Question: What is the difference between memcpy() and
     memmove()?

Answer: memcpy copies n bytes between non-overlapping regions;
overlapping source and destination produce undefined behavior. memmove
is specifically defined to handle overlap safely, usually by choosing a
copy order or temporary strategy.

Example: memmove(buf+1, buf, 5); // safe for overlap; memcpy(buf+1, buf,
5) is not valid for overlapping regions

should explicitly track destination capacity and choose an appropriate

104. [COMMON] Question: What is the difference between strlen() and
     sizeof() for strings?

Answer: strlen measures the number of characters before the first ‘\0’
in a C string at runtime. sizeof gives the size in bytes of an
object/type at compile time (except for VLA cases). For char arr[] =
“hello”, sizeof(arr) is 6 including the terminator, while strlen(arr) is
5.

Example: char s[]=“hello”; printf(“%zu %zu”, strlen(s), sizeof(s)); // 5
6

functions where appropriate, macros, or generic facilities such as

167. [FOLLOW-UP] Question: You said volatile prevents optimization. Does
     it make counter++ atomic?

Answer: volatile tells the implementation that accesses to the object
are observable and should not be optimized away or merged in ways that
violate the language’s volatile-access rules. It is useful for
memory-mapped hardware and some signal/ISR scenarios. It does not make
compound operations atomic and does not by itself provide thread
synchronization.

and the original allocation remains valid. This is why assigning realloc
directly to the only pointer can lose the original address.

207. [HIGH-VALUE] Question: Why is strcpy() dangerous?

Answer: strcpy copies characters until the terminating null byte and
assumes the destination has enough space. If the destination buffer is
too small, it can overflow and cause undefined behavior. Bounded designs
should explicitly track destination capacity and choose an appropriate
API/strategy.

use-after-free, stack overflow, and corrupted addresses. The exact

Answer: A typical C build preprocesses source, compiles it to assembly
or an equivalent intermediate form, assembles it into object code, then
links object files and libraries into an executable or shared object. A
compiler error is usually a source-language/type/syntax diagnostic; a
linker error commonly means a required symbol definition or library
could not be resolved.

211. [HIGH-VALUE] Question: Reverse a linked list.

Answer: A linked list is a sequence of nodes connected through pointers.
A singly linked list stores a value and a pointer to the next node. It
supports efficient insertion/removal when the relevant node/link is
already known, but random indexing is O(n).

Example: Node prev = NULL, cur = head; while (cur) { Node *next =
cur->next; cur->next = prev; prev = cur; cur = next; } head = prev;

218. [HIGH-VALUE] Question: Solve a bitwise/bitmask problem.

Answer: Use bitwise operators intentionally: & tests/masks bits, | sets
selected bits, ^ toggles bits, and ~ complements bits. To set bit k use
x |= (1u << k); to clear use x &= ~(1u << k); to toggle use x ^= (1u <<
k); to test use (x & (1u << k)) != 0. Use unsigned types for predictable
bitwise reasoning.

Example: unsigned x = 0; x |= (1u<<3); x &= ~(1u<<3); x ^= (1u<<3);
