PYTHON INTERVIEW QUESTIONS — CLEAN EDITORIAL EDITION

Category : Python
Topics : built-in types, functions, OOP, iterators, generators, exceptions, concurrency and asyncio
Audience : Fresher, intermediate and experienced candidates
Format : Question : / Answer : / Example :
Editorial standard : Clear, practical interview preparation with concrete examples. Examples are illustrative unless the question explicitly preserves a source/report label.

Question : What is the difference between a list and a tuple?
Answer : A list is mutable, while a tuple is immutable after creation. Lists are suited to collections that need modification; tuples are useful for fixed records and can be hashable when all their elements are hashable. Both preserve order and can contain duplicate values.
Example : Suppose an API returns a list of order IDs that the application later needs to modify. A list is appropriate for the working collection, while a tuple can represent a fixed coordinate such as `(latitude, longitude)`. For example: `orders = [101, 102]; orders.append(103)` and `location = (18.52, 73.85)`.

Question : What does dynamically typed mean in Python?
Answer : Python is dynamically typed because variable names are not permanently associated with one declared type. The object referenced by a name has a type, and that type is determined at runtime. A name can later refer to an object of another type. Dynamic typing is different from weak typing; Python still enforces type rules when operations are performed.
Example : A function can accept a value whose type is only known when the code runs. For example, `value = 10; value = '10'` is valid because the name is rebound to a new object; the operation performed on that object still has to be type-compatible.

Question : Is Python compiled, interpreted, or both?
Answer : Python is commonly described as interpreted, but CPython first compiles source code to bytecode and then executes that bytecode on the Python virtual machine. The important interview point is that compilation to bytecode does not make Python equivalent to a traditionally ahead-of-time compiled language such as C. Other Python implementations can use different execution strategies.
Example : When CPython runs `report.py`, the source is parsed and compiled to bytecode before execution by the Python runtime. That is why saying simply 'Python is interpreted' is useful as a shorthand, but incomplete when discussing how CPython actually executes code.

Question : == vs is in Python?
Answer : == tests value equality, while is tests object identity—whether two references point to the same object. Use == when comparing values and is mainly for identity checks such as x is None. Do not rely on implementation-specific interning or caching to make is work for ordinary values.
Example : If `a = [1, 2]` and `b = [1, 2]`, then `a == b` is `True` because the values match, while `a is b` is `False` because they are different list objects. In production code, `is None` is the common identity check.

Question : How does Python pass arguments to functions?
Answer : Python uses call-by-sharing (also called object-reference semantics): the function receives a reference to the same object bound to the argument. Rebinding a parameter does not rebind the caller’s variable, but mutating a shared mutable object is visible to the caller. This explains why mutable and immutable arguments can appear to behave differently.
Example : If a function appends to a list passed by the caller, the caller sees the mutation because both references point to the same list. If the function instead assigns `items = []`, it only rebinds the local parameter. This distinction is often the cleanest way to explain Python's call-by-sharing model.

------------------------------------------------------------------------------

Question : What are mutable and immutable objects?
Answer : Mutable objects can be changed after creation; immutable objects cannot be changed in place. Common mutable types include list, dict, and set. Common immutable types include int, float, bool, str, and tuple (although a tuple can contain mutable objects). Immutability is important for hashing and for understanding whether a function mutates shared state.
Example : A configuration object can be a mutable dictionary when fields need to change, while a string such as an environment name is immutable. `config['timeout'] = 30` changes the dictionary; `name += '-prod'` creates a new string rather than modifying the old one.

------------------------------------------------------------------------------

Question : Why are default mutable arguments dangerous?
Answer : Default argument expressions are evaluated once when the function is defined, not each time it is called. If the default is mutable, calls can accidentally share the same object and retain state between calls. The standard safe pattern is to use None as the default and create a new object inside the function.
Example : A common bug is `def add_user(name, users=[]): ...`, where the same list survives across calls. The safer version is `def add_user(name, users=None): users = [] if users is None else users`. Each call then gets a fresh list unless the caller deliberately supplies one.

Question : *args vs **kwargs?
Answer : *args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dictionary. They are useful for flexible APIs and wrappers, but should not be used merely to hide unclear function contracts.
Example : A logging wrapper may need to accept arbitrary positional and keyword arguments: `def log_call(*args, **kwargs): ...`. `args` is a tuple and `kwargs` is a dictionary, which makes the wrapper flexible without forcing every wrapped function to have the same signature.

------------------------------------------------------------------------------

Question : How do list comprehensions work?
Answer : A list comprehension creates a list from an iterable using an expression and optional filtering condition. It is concise for straightforward transformations, but nested or highly complex comprehensions can reduce readability. It eagerly creates the resulting list in memory.
Example : For a report that needs only even transaction amounts, `amounts = [x for x in values if x % 2 == 0]` is concise and readable. If the filtering rules become several lines long, a normal loop is usually easier for another engineer to maintain.

------------------------------------------------------------------------------

Question : Generator expression vs list comprehension?
Answer : A list comprehension eagerly builds the complete list. A generator expression produces values lazily as they are requested, so it generally uses less memory for large or streaming workloads. A generator can be consumed only as it yields values and does not provide normal list operations such as indexing.
Example : If a service needs to sum millions of generated values, `sum(x*x for x in range(10_000_000))` avoids building a ten-million-element list first. If the caller needs indexing or repeated iteration, a list may be the better choice.

------------------------------------------------------------------------------

Question : Iterator vs iterable?
Answer : An iterable is an object that can provide an iterator, usually through __iter__(). An iterator represents the state of an ongoing traversal and implements __next__(), raising StopIteration when exhausted. Every iterator is iterable, but not every iterable is itself an iterator.
Example : A list is iterable because `iter(items)` can create an iterator from it. The iterator keeps traversal state, so `next(it)` returns the next element and eventually raises `StopIteration`. That difference matters when explaining why a `for` loop can consume a generator only once.

Question : What does yield do?
Answer : yield turns a function into a generator function. Instead of returning once and ending, it produces a value and suspends execution, preserving local state so execution can continue on the next iteration. This is useful for streaming large or incremental results without storing them all in memory.
Example : A generator such as `def read_ids(): yield from database_cursor` can produce one ID at a time. The caller can process the first few records without waiting for the entire result set to be stored in memory.

Question : How would you read a large file without loading it into memory?
Answer : Process the file incrementally, typically by iterating over the file object line by line or by using a suitable chunk size. This keeps memory usage roughly independent of the total file size. For very large files, combine streaming with filtering, batching, and controlled output writes.
Example : For a 20 GB application log, use `with open('events.log', encoding='utf-8') as f:` and process each line or a controlled chunk. The program can filter errors and write summaries without ever holding the entire file in RAM.

------------------------------------------------------------------------------

Question : Shallow copy vs deep copy?
Answer : A shallow copy creates a new outer container but keeps references to nested objects. A deep copy recursively copies nested objects as well. Shallow copying is usually cheaper and is enough when nested objects are intentionally shared; deep copying is useful when complete independence is required, but it can be expensive and may not work meaningfully for every object.
Example : If `orders = [{'id': 1, 'items': [...] }]`, a shallow copy duplicates the outer list but still shares each nested dictionary. A deep copy recursively duplicates nested objects. I would choose shallow copy when shared nested state is intentional and deep copy only when true independence is required.

Question : How does Python garbage collection work?
Answer : CPython primarily uses reference counting to reclaim objects whose reference count reaches zero, plus a cyclic garbage collector to detect reference cycles that reference counting alone cannot reclaim. Other Python implementations can use different memory-management strategies. Garbage collection is automatic, but resource management such as files and sockets should not be left to garbage collection; use explicit cleanup or context managers.
Example : In CPython, reference counting normally reclaims an object when its count reaches zero, while cyclic garbage collection handles cycles that reference counting alone cannot reclaim. A file should still be closed explicitly with `with open(...)`; garbage collection is not a substitute for deterministic resource cleanup.

------------------------------------------------------------------------------

Question : What is reference counting?
Answer : In CPython, each object maintains a reference count. When the count reaches zero, the object’s memory can generally be reclaimed immediately. Reference counting alone cannot collect cycles because objects in a cycle can keep references to each other even when no outside references remain, which is why CPython also has cyclic garbage collection.
Example : If `a = []; b = a; del a`, the list remains alive because `b` still references it. Once the last reference is removed, CPython can normally reclaim the object immediately through reference counting.

------------------------------------------------------------------------------

Question : What is the GIL?
Answer : In the traditional GIL-enabled CPython build, the Global Interpreter Lock means only one thread at a time executes Python bytecode within a process. That limits parallel execution of CPU-bound pure-Python code in threads, while I/O-bound threads can still overlap when they spend time waiting. This is an implementation detail of CPython, not a rule that applies identically to every Python implementation; current Python releases also provide free-threaded builds, so I would state the version/build when answering a GIL question.
Example : On a traditional GIL-enabled CPython build, two CPU-heavy Python threads generally do not execute Python bytecode in parallel on separate cores. The same threads can still be useful for network or file I/O because blocking operations can release the GIL. Python also has free-threaded builds, so the exact statement should identify the build/version.

------------------------------------------------------------------------------

Question : How does the GIL affect CPU-bound threads?
Answer : For CPU-bound pure-Python work in traditional CPython, the GIL prevents multiple threads from executing Python bytecode simultaneously within one process, so adding threads often does not provide linear CPU scaling and may add scheduling overhead. CPU-bound work can instead be parallelized with multiprocessing or suitable native/vectorized code that releases the GIL.
Example : If two threads both spend most of their time calculating Fibonacci numbers in pure Python, adding more threads is unlikely to give the expected CPU scaling on a traditional GIL-enabled CPython build. Moving independent CPU-heavy work to processes is often a better fit.

------------------------------------------------------------------------------

Question : When would you use multiprocessing?
Answer : Use multiprocessing when work is CPU-bound and can be divided into independent tasks, especially when native parallelism across CPU cores is needed in traditional CPython. Processes have separate memory spaces, so communication and data transfer cost more than threads. It is less attractive for tiny tasks or workloads dominated by shared mutable state.
Example : A thumbnail service that resizes thousands of independent images can use a process pool so work runs across CPU cores. The trade-off is process startup, memory use, and data-transfer overhead, so the job size should justify the parallelism.

------------------------------------------------------------------------------

Question : Threading vs multiprocessing vs asyncio?
Answer : Threading is useful for overlapping blocking I/O within one process and sharing memory conveniently, but CPU-bound Python code is constrained by the traditional CPython GIL. Multiprocessing provides separate processes and can use multiple CPU cores, at the cost of higher memory and communication overhead. asyncio uses cooperative scheduling with async/await and is effective for high-concurrency non-blocking I/O when the libraries used are asyncio-compatible. The workload and ecosystem should determine the choice.
Example : For an API that waits on many network calls, asyncio can provide high concurrency with async-compatible clients. For a legacy blocking SDK, threads may be simpler. For CPU-heavy Python calculations, processes are usually the more natural choice.

Question : What is a decorator?
Answer : A decorator is a callable that takes a function or class and returns a modified or wrapped callable. It is commonly used for cross-cutting behavior such as logging, authorization, timing, caching, and retries without changing the wrapped function’s core implementation. functools.wraps should normally be used so metadata such as the original function’s name and docstring is preserved.
Example : A request decorator can record execution time without changing the endpoint's core logic. Using `functools.wraps` keeps the wrapped function's name and documentation intact, which helps debugging and introspection.

------------------------------------------------------------------------------

Question : How do you write a decorator that accepts arguments?
Answer : A decorator with arguments needs one additional function layer: the outer function receives the decorator configuration, the middle function receives the target function, and the inner wrapper executes the function. functools.wraps should be applied to the wrapper.
Example : For a decorator such as `@retry(3)`, the outer function receives `3`, the middle function receives the target function, and the inner wrapper performs the calls. The extra layer is what lets the decorator accept configuration before it sees the function.

------------------------------------------------------------------------------

Question : What is a context manager?
Answer : A context manager defines setup and cleanup behavior around a block of code. It implements __enter__ and __exit__, or can be created conveniently with contextlib.contextmanager. Context managers are ideal for resources that must be released reliably, including files, locks, database transactions, and temporary state.
Example : Database code can use a context manager to ensure a connection or transaction is cleaned up even when an exception occurs. The same idea applies to files, locks, temporary directories, and other resources with a clear lifecycle.

------------------------------------------------------------------------------

Question : How does the with statement work?
Answer : with obtains a context manager, calls its __enter__, assigns the returned value if an as target is present, executes the block, and then calls __exit__ during cleanup, including when an exception occurs. The return value of __exit__ can determine whether an exception is suppressed. This provides structured resource management.
Example : With `with lock: update_cache()`, Python enters the lock context before the block and exits it afterward. If `update_cache()` raises, the context manager still gets its cleanup opportunity, which is why `with` is safer than manually acquiring and releasing resources in separate statements.

Question : How would you define and raise a custom exception?
Answer : Create a class inheriting from an appropriate built-in exception, then raise it with raise. Custom exceptions make domain-specific failures explicit and allow callers to catch a precise type. Avoid creating many exception classes when existing standard exceptions already express the condition clearly.
Example : A payment domain can define `class InsufficientFundsError(Exception): pass` and raise it when a withdrawal cannot be completed. The caller can then handle that business condition separately from an unexpected database or programming failure.

------------------------------------------------------------------------------

Question : How should exceptions be handled in production code?
Answer : Catch exceptions at the layer that can meaningfully handle them. Avoid broad except Exception blocks that silently hide failures; when broad catches are necessary at a boundary, log useful context and re-raise or convert the error appropriately. Preserve exception causes with raise ... from ..., avoid leaking secrets in logs, and distinguish expected business errors from programming defects. External operations should also have appropriate timeouts and retry policies.
Example : At an HTTP boundary, I might catch a known `PaymentDeclined` exception and return a controlled response, while logging unexpected exceptions with `logger.exception(...)` and allowing them to reach monitoring. I would avoid swallowing `Exception` silently because that turns real defects into hard-to-diagnose failures.

Question : dict vs defaultdict vs Counter?
Answer : dict is the standard mapping and requires explicit handling for missing keys. defaultdict supplies a default value through a factory when a missing key is accessed, which is convenient for grouping or accumulation. Counter is specialized for counting hashable elements and provides operations tailored to frequency analysis.
Example : For grouping, `defaultdict(list)` avoids repeatedly checking whether a key exists. For frequency analysis, `Counter` directly expresses the intent. A normal `dict` remains the best default when missing-key behavior needs to be explicit.

Question : How do sets remove duplicates?
Answer : A set stores unique hashable elements, so converting a sequence to a set removes duplicate values. Sets do not preserve duplicates and should not be used when duplicates or stable list semantics are required. Set membership is typically average O(1), making sets useful for fast membership checks.
Example : If a user submits `[101, 101, 102, 103, 103]`, `set(values)` gives the unique values. If the requirement is to keep the original order, use a different approach such as a seen set plus a result list rather than relying on set ordering.

Question : How would you sort a dictionary by value?
Answer : Use sorted() on the dictionary’s items with a key function selecting the value. sorted() returns a list of tuples; if a dictionary is required afterward, construct one from that result. State whether ascending/descending order and tie behavior matter.
Example : Given `scores = {'Alice': 82, 'Bob': 95, 'Cara': 88}`, `sorted(scores.items(), key=lambda item: item[1], reverse=True)` produces entries from highest score to lowest. I would keep the result as a list unless the next operation specifically requires a dictionary.

------------------------------------------------------------------------------

Question : append() vs extend()?
Answer : append(x) adds one object as a single element. extend(iterable) iterates over the supplied iterable and adds each element. This distinction is common in interviews because appending a list produces a nested list, while extending with a list adds its members.
Example : `append([3, 4])` adds one list as a single element, producing `[1, 2, [3, 4]]`. `extend([3, 4])` adds the two elements and produces `[1, 2, 3, 4]`. The right method depends on whether the incoming object should remain one item or be unpacked.

------------------------------------------------------------------------------

Question : How would you reverse a string?
Answer : Strings are immutable, so reversing creates a new string. Python slicing with a step of -1 is concise; reversed() can also be used and returns an iterator that can be joined. Choose the clearest approach for the context.
Example : For a short utility function, `reversed_text = text[::-1]` is simple and readable. If the code is already working with an iterator and does not need a new string immediately, `reversed(text)` can be more appropriate.

------------------------------------------------------------------------------

Question : How would you find duplicate values in a list?
Answer : Maintain a set of values already seen and another set for duplicates. For each value, if it is already in the seen set, add it to duplicates; otherwise add it to seen. This gives average O(n) time for hashable values and preserves a clear separation between seen values and confirmed duplicates.
Example : For `[4, 2, 4, 7, 2]`, keep `seen` and `duplicates` sets while scanning once. The first `4` enters `seen`; the second `4` enters `duplicates`. This avoids repeatedly scanning the list and gives average O(n) time for hashable values.

------------------------------------------------------------------------------

Question : How would you find the first non-repeating character?
Answer : Count character frequencies first, then scan the original string in order and return the first character whose count is one. This preserves the required original ordering and is typically O(n) time with O(k) additional space for distinct characters.
Example : For `'swiss'`, first count characters with `Counter`, then scan the original string. The counts show `s` appears three times, `w` once, and `i` once; the first character with count one is `w`.

------------------------------------------------------------------------------

Question : How would you implement binary search?
Answer : Binary search works on sorted data by comparing the target with the middle element and discarding half the remaining search interval each step. It runs in O(log n) time and O(1) extra space for an iterative implementation. Correct boundary handling is the main interview challenge.
Example : For a sorted list such as `[3, 7, 12, 18, 25]`, compare the target with the middle element and discard the half that cannot contain it. The key interview detail is maintaining correct `lo` and `hi` boundaries so the search terminates.

------------------------------------------------------------------------------

Question : How would you merge two sorted lists?
Answer : Use two pointers, one for each sorted list. Compare the pointed values, append the smaller one, and advance that pointer. After one list is exhausted, append the remaining elements of the other list. The time complexity is O(n+m) and extra space is O(n+m) for a new result.
Example : To merge `[1, 4, 7]` and `[2, 3, 8]`, compare the front elements, take the smaller one, and advance only that pointer. The result is `[1, 2, 3, 4, 7, 8]` in O(n+m) time.

Question : How would you count word frequencies in a large text file?
Answer : Read the file incrementally rather than loading it all into memory, tokenize each line or chunk, and accumulate counts in a Counter or dictionary. Define normalization rules such as case folding and punctuation handling before counting. For extremely large or distributed data, use batching or an external aggregation system.
Example : For a multi-gigabyte log, iterate over lines and update a `Counter` instead of calling `.read()` on the whole file. If the definition of a word includes punctuation or case normalization, decide those rules before counting so the result is consistent.

Question : How would you remove duplicates while preserving order?
Answer : Use a set to track values already seen while iterating through the original sequence and append each unseen value to a result list. This preserves first-occurrence order and is typically O(n) average time for hashable values.
Example : If `[3, 1, 3, 2, 1]` must become `[3, 1, 2]`, maintain a `seen` set and append only values that have not appeared before. This preserves the first occurrence of each value.

Question : How would you find the second-largest number?
Answer : Clarify whether the requirement means the second distinct largest value. For a distinct result, maintain the largest and second-largest values while scanning once, handling duplicates explicitly. Sorting is simpler but costs O(n log n); a one-pass solution can be O(n).
Example : For `[10, 4, 10, 7, 3]`, track the largest and second-largest distinct values in one pass. The answer is `7`; the important detail is deciding whether duplicates count as the same value before writing the algorithm.

Question : How would you detect a cycle in a linked list?
Answer : Use Floyd’s tortoise-and-hare algorithm: move one pointer one step and another two steps. If they ever meet, a cycle exists. If the fast pointer reaches the end, there is no cycle. This uses O(n) time and O(1) extra space.
Example : For a linked-list cycle, use Floyd's tortoise-and-hare algorithm: move one pointer one step and the other two steps. If they meet, there is a cycle; if the fast pointer reaches the end, there is not. The method uses O(1) extra space.

Question : How does asyncio work?
Answer : asyncio provides cooperative concurrency around an event loop. Async functions create coroutines; when a coroutine reaches an awaitable operation that is not ready, control returns to the event loop so another task can run. It is effective for high-concurrency I/O when operations are non-blocking and async-compatible. Blocking calls inside the event loop can stall all tasks.
Example : An asyncio application runs coroutines on an event loop. When a coroutine reaches an `await` for unfinished I/O, it yields control so another ready task can run. This makes asyncio useful for high-concurrency I/O without requiring one OS thread per connection.

------------------------------------------------------------------------------

Question : async def vs normal def?
Answer : `async def` defines a coroutine function. Calling it creates a coroutine object; its body does not simply run to completion like a normal `def` call. The coroutine runs when it is awaited or scheduled as a task. A normal `def` runs synchronously until it returns or raises, unless it delegates work elsewhere.
Example : A normal `def` executes when called and returns its result directly. An `async def` creates a coroutine object when called; its body runs when the coroutine is awaited or scheduled as a task. That distinction is why forgetting to await an async function can produce warnings and missing work.

------------------------------------------------------------------------------

Question : await vs create_task()?
Answer : `await` waits for an awaitable from the current coroutine and gives the event loop an opportunity to run other ready work while the awaited operation is incomplete. `asyncio.create_task()` schedules a coroutine as a separate Task so it can make progress concurrently with the current coroutine. Tasks should be retained and awaited, or managed with a `TaskGroup`, so completion and exceptions are not accidentally ignored.
Example : `await fetch(url)` waits for that operation from the current coroutine, while `asyncio.create_task(fetch(url))` schedules the coroutine to run concurrently with other tasks. If I create tasks, I also keep references to them and await their completion or use a `TaskGroup` so failures are handled predictably.

Question : When is asyncio a bad fit?
Answer : asyncio is a poor fit when the workload is CPU-bound, when the main libraries are blocking and cannot be adapted safely, or when the application’s concurrency is small enough that synchronous code is substantially simpler. It can still coexist with blocking work by moving that work to an executor/thread/process, but that adds complexity.
Example : Asyncio is a poor fit when the workload is dominated by CPU-heavy Python code or when the important libraries are blocking and have no practical async interface. In those cases, processes or threads can be simpler and more effective.

Question : How would you debug a slow Python service?
Answer : Start with measurements: latency percentiles, throughput, error rates, CPU, memory, I/O, database time, external-call time, and queue/pool waits. Use tracing or profiling to identify where time is actually spent. Check recent deployments and workload changes, then isolate the bottleneck and make one targeted change at a time. Do not assume Python code is the bottleneck when database or network waits may dominate.
Example : For a slow endpoint, start with evidence: compare p50/p95 latency, inspect traces, database timings, external calls, CPU, memory, and request volume. I would avoid rewriting code before identifying which component actually dominates the latency.

Question : How would you profile Python code?
Answer : Use the least invasive tool that answers the question. Deterministic profilers such as cProfile help identify function-level CPU time; sampling profilers can be useful for production-like workloads; line-level profiling can isolate expensive code paths. For memory, use tools such as tracemalloc to compare allocations. Profile representative workloads and compare before/after measurements.
Example : Use a profiler or sampling profiler to identify where time is really being spent. For example, if a profile shows most CPU time in JSON serialization, optimizing database code would not address the main bottleneck.

------------------------------------------------------------------------------

Question : What is the difference between time complexity and actual performance?
Answer : Time complexity describes how an algorithm’s resource usage grows asymptotically with input size; it does not predict exact wall-clock time. Actual performance depends on constants, Python interpreter overhead, memory locality, allocations, I/O, hardware, database/network latency, and workload shape. Two O(n) implementations can have very different real-world performance.
Example : Big-O describes how an algorithm scales as input grows; it does not predict the exact runtime on a real machine. Cache behavior, constant factors, Python interpreter overhead, I/O, data distribution, and the actual input size all affect measured performance.

------------------------------------------------------------------------------

Question : How can excessive object creation affect Python performance?
Answer : Creating many temporary Python objects consumes CPU for allocation and initialization and increases memory pressure and garbage-collection work. It can also increase cache and allocator overhead. Reducing unnecessary intermediate objects, using streaming approaches, batching, or specialized libraries can improve performance when profiling shows allocation is significant.
Example : Creating millions of short-lived objects increases allocation and deallocation work and can increase memory pressure. If a hot loop repeatedly constructs temporary dictionaries, for example, reducing unnecessary allocations can improve both CPU time and memory behavior.

------------------------------------------------------------------------------

Question : How would you optimize a slow loop?
Answer : Measure first to identify the loop’s actual bottleneck. Then consider algorithmic improvements, moving invariant work outside the loop, choosing appropriate data structures such as sets for membership, reducing allocations, using built-ins implemented efficiently, batching I/O, or vectorizing with an appropriate library. Preserve correctness and benchmark representative input after each change.
Example : If a loop repeatedly searches a list for membership, replacing the inner linear search with a set can change the algorithm from roughly O(n²) to average O(n) for hashable values. I would profile first so the optimization targets a real hotspot rather than an assumed one.

------------------------------------------------------------------------------

Question : How do generators help with memory usage?
Answer : Generators produce values lazily instead of storing the complete result. This lets pipelines process one item at a time and keeps memory usage bounded by the current working state rather than the total number of items. They are particularly useful for files, streams, and large sequences.
Example : A generator can stream records from a database cursor or file so only a small amount of data is held at once. That is especially useful when the consumer can process records incrementally rather than needing random access to the whole collection.

Question : How would you write a thread-safe Singleton if a Singleton were actually required?
Answer : First challenge the requirement because global singletons can create hidden state and make testing harder. If one is genuinely required, make initialization and access synchronization explicit, and ensure the implementation is correct under concurrent access. Depending on the application, a module-level object is often simpler in Python; if lazy initialization is needed, a lock can protect creation.
Example : If a Singleton is genuinely required, protect initialization with a lock and make the lifecycle explicit. In many applications I would prefer dependency injection or a module-level object instead, because those designs are easier to test and reason about than hidden global state.

Question : What are Python dataclasses?
Answer : Dataclasses are a standard-library feature for classes primarily used to hold data. The @dataclass decorator can generate methods such as __init__, __repr__, and comparisons based on declared fields. Options such as frozen, slots, defaults, and keyword-only fields let the class model be tuned to the use case.
Example : A dataclass is useful for data-focused classes where generated methods such as `__init__`, `__repr__`, and comparisons reduce boilerplate. For example, `@dataclass class User: id: int; name: str` clearly expresses the shape of the data while still allowing normal methods and validation when needed.

Question : How does inheritance work in Python?
Answer : Python supports single and multiple inheritance. A subclass inherits attributes and methods from its base classes and can override them. Attribute lookup follows the method resolution order (MRO), which becomes important with multiple inheritance. super() provides cooperative access to the next implementation in the MRO.
Example : A derived class inherits attributes and methods from a base class and can override behavior. For example, `PremiumCustomer` can inherit common customer behavior while overriding `discount()` to apply a different rule. Composition may still be preferable when the relationship is not truly 'is-a'.

------------------------------------------------------------------------------

Question : classmethod vs staticmethod?
Answer : A classmethod receives the class as its first argument, conventionally cls, and is useful for alternate constructors or behavior that depends on class state. A staticmethod receives neither an implicit instance nor class and is essentially a namespaced function. A normal instance method receives self.
Example : Use `@classmethod` when the method needs the class (`cls`), often for alternate constructors. Use `@staticmethod` when the operation belongs conceptually to the class but needs neither the class nor instance (`self`). The choice should reflect what state the method actually needs.

------------------------------------------------------------------------------

Question : What is method resolution order (MRO)?
Answer : MRO is the order Python uses to search classes for attributes and methods, especially with inheritance and multiple inheritance. Python uses the C3 linearization algorithm. Class.mro() or Class.__mro__ shows the order. Understanding MRO explains how super() behaves in cooperative multiple inheritance.
Example : If `class Child(Left, Right)` inherits from multiple classes, Python uses the method resolution order to determine where it looks for attributes and methods. `Child.mro()` shows the order, which is especially useful when multiple base classes define the same method.

------------------------------------------------------------------------------

Question : What are dunder methods?
Answer : Dunder, or double-underscore, methods are special methods such as __init__, __len__, __eq__, and __iter__ that define how objects interact with Python language features and operators. They should normally be implemented according to Python’s data model rather than called directly without reason.
Example : Dunder methods such as `__len__`, `__iter__`, `__eq__`, and `__enter__` let objects participate naturally in Python protocols. For example, implementing `__len__` allows `len(cart)` to express the object's intended behavior instead of exposing an unrelated helper method.

Question : How does eq relate to object equality?
Answer : __eq__ defines how == compares instances of a class. If a class implements value-based equality, it should also have a compatible hashing design: mutable objects whose equality-relevant state can change generally should not be hashable. Python’s dataclass behavior also depends on options such as eq and frozen.
Example : If a `User` class implements `__eq__` to compare IDs, `user1 == user2` can be true even when the objects are different instances. Equality should describe the domain meaning of sameness; identity checks with `is` answer a different question.

Question : How do you make an object hashable?
Answer : An object is hashable when it has a stable hash value for its lifetime and can be compared for equality consistently, allowing it to be used as a dictionary key or set element. If a class overrides `__eq__()` without defining a compatible `__hash__()`, Python normally makes instances unhashable. Mutable state that affects equality should not be allowed to change while the object is stored in a hashed collection.
Example : If an object is used as a dictionary key, its equality and hash must remain consistent. A frozen dataclass containing immutable fields is often a clean choice. If an object's fields used for hashing can change, it should generally not be hashable.

Question : How would you safely manage database connections?
Answer : Use a connection pool when appropriate, parameterized queries, explicit transaction boundaries, and context-manager-style cleanup so connections are always returned. Configure connection timeouts and pool limits, monitor pool exhaustion, and avoid keeping transactions open longer than necessary. The exact API depends on the database driver or ORM.
Example : Use a connection pool when an application handles many database requests rather than opening a brand-new connection for every request. Acquire the connection for the shortest useful scope, return it to the pool reliably, configure timeouts, and ensure transactions are committed or rolled back correctly.

Question : How do parameterized SQL queries prevent injection?
Answer : Parameterized queries keep SQL structure separate from user-supplied values. The driver sends the statement and parameters separately or otherwise safely binds them, so input such as quotes or SQL operators is treated as data rather than executable SQL. Dynamic identifiers still require controlled allow-lists because they are not ordinary values.
Example : Never build SQL by concatenating untrusted input such as `f"SELECT ... WHERE id = {user_id}"`. Use the database parameterized-query API so the value is transmitted as data rather than being parsed as part of the SQL statement.

Question : How would you design a Python REST API?
Answer : Define resources and HTTP semantics first, then structure the application into routing, validation, service/business logic, data-access, and error-handling layers. Add authentication/authorization, request validation, timeouts, logging, metrics, tracing, consistent error responses, pagination, and database transaction boundaries. Use dependency injection or clear interfaces where it improves testability, and keep external calls resilient.
Example : For a production REST API, define resources and HTTP semantics clearly, validate input at the boundary, separate business logic from transport code, return consistent error responses, add authentication/authorization where required, and instrument latency and failures. The design should also cover pagination, timeouts, idempotency, and versioning where the use case needs them.

Question : How would you validate request data?

Validate types, required fields, ranges, formats, and cross-field rules. Never treat client validation as a security boundary; authorization and database constraints are still required.
Example : Validate request data before it reaches business logic. Check types, required fields, ranges, formats, and cross-field rules, then return a clear client error without exposing internal stack traces. A schema-validation library can centralize these rules and keep endpoint code focused.

Question : How would you structure a production Python project?

Keep configuration externalized, dependencies explicit, logging structured, and modules cohesive. The exact layout can vary by framework, but production structure should make testing, deployment, and ownership straightforward.
Example : A maintainable Python service might separate application code, domain logic, infrastructure adapters, tests, configuration, and deployment files. The exact layout should match the project size; the goal is clear ownership of responsibilities rather than following a directory template mechanically.

Question : How would you write unit tests with pytest?

Mock external dependencies when the unit’s purpose is to test its own logic, while keeping separate integration tests for real database/network interactions.
Example : With pytest, keep tests focused on one behavior and use fixtures for reusable setup. For example, a test for `calculate_total()` can provide a small cart fixture and assert the expected total. Parameterization is useful when the same rule has several important inputs.

Question : Mocking vs integration testing?
Answer : Mocking replaces a dependency with a controlled test double and is useful for isolating unit behavior, simulating failures, and making tests fast. Integration tests exercise real component boundaries such as a database, queue, or HTTP service and catch wiring/configuration issues that mocks can miss. A healthy test suite uses both at appropriate levels rather than mocking everything.
Example : A unit test isolates a component and is fast enough to run frequently. An integration test verifies that multiple real components work together, such as an API talking to a real database. Mocking is useful when an external dependency is slow, costly, or nondeterministic, but excessive mocking can make tests pass without proving the real integration works.

Question : How would you diagnose a memory leak in a Python service?
Answer : First distinguish a true leak from legitimate cache growth, fragmentation, workload growth, or retained references. Track process RSS and Python allocation trends, then use tools such as tracemalloc to compare snapshots and identify growing allocation sites. Inspect global containers, caches, callbacks, task references, and long-lived objects. Reproduce under controlled load and verify that memory stabilizes after the workload ends.
Example : First establish whether memory usage is actually leaking or simply growing with legitimate workload. Compare object counts over time, take memory snapshots, inspect retained references, and check caches, global collections, queues, and native extensions. Reproduce the growth under controlled load before changing code.

Question : How would you handle retries when calling an external API?
Answer : Retry only failures that are transient and safe to retry. Use timeouts, bounded retries, exponential backoff with jitter, and ideally idempotency keys for operations that could otherwise be performed twice. Do not retry authentication errors or permanent validation failures blindly. Set an overall deadline and surface failure after the retry budget is exhausted.
Example : Retry only failures that are likely transient, such as selected network timeouts or temporary service-unavailable responses. Use bounded retries, exponential backoff with jitter, and an overall timeout. Do not blindly retry non-idempotent operations because a timeout can occur after the remote service has already completed the request.

Question : How would you prevent duplicate processing of the same request?
Answer : Use an idempotency key or unique business identifier, persist the processing state atomically, and make repeated requests return the existing result or safely perform no additional effect. For asynchronous consumers, combine durable message handling with an idempotency record or unique constraint. The database should enforce uniqueness where possible rather than relying only on in-memory checks.
Example : Give each request a stable idempotency key and enforce uniqueness at the durable boundary when possible. If the same request arrives twice, return the stored result or safely reuse the existing operation rather than creating a second side effect.

Question : How would you process a CSV file containing tens of millions of rows?
Answer : Stream the file rather than reading it into memory. Parse and validate rows incrementally, batch database inserts or downstream operations, use bounded queues if producer/consumer concurrency is helpful, and checkpoint progress so failures can resume. Monitor throughput, memory, error rates, and database load. For very large data loads, database-native bulk-loading tools may be preferable to row-by-row INSERTs.
Example : For tens of millions of CSV rows, stream the file, validate records incrementally, batch downstream writes, and monitor memory and throughput. If the database provides a bulk-load mechanism, compare it with row-by-row inserts because it may be substantially more efficient.

Question : How would you make a Python job idempotent?
Answer : Define a stable operation key and make repeated executions produce the same intended final state rather than duplicate side effects. Persist progress or processed identifiers, use unique constraints or upserts where appropriate, and make external calls idempotent when possible. Test retries and partial failures explicitly.
Example : For a daily invoice job, use a stable `invoice_id` or job key and make the database write idempotent with a unique constraint or upsert. If the scheduler runs the job twice, the second execution should converge on the same final state rather than create another invoice.

Question : How would you handle concurrent updates to shared state?
Answer : First determine whether shared mutable state can be eliminated or partitioned. If it must be shared between threads, protect critical sections with appropriate synchronization such as locks or thread-safe queues. For processes, use suitable inter-process primitives or external durable storage. In distributed systems, coordinate through the database or another shared consistency mechanism rather than relying on a Python lock that exists in only one process.
Example : If several threads update a shared counter, protect the read-modify-write operation with a synchronization primitive such as `threading.Lock`, or redesign the state so threads do not share mutable data. In a multi-process or distributed system, a Python lock in one process is not sufficient coordination.

Question : How would you choose between threads and asyncio for an I/O-heavy service?
Answer : Choose asyncio when the service has high concurrency, the I/O libraries are async-compatible, and cooperative scheduling provides a clear benefit. Choose threads when existing blocking libraries are easier to use and concurrency requirements are moderate. Consider operational simplicity, cancellation behavior, connection-pool support, and team familiarity—not just raw throughput.
Example : For a high-concurrency service using async HTTP/database clients, asyncio is a natural fit. For an existing blocking SDK with moderate concurrency, a thread pool may require less redesign. I would decide based on the actual libraries, cancellation behavior, connection pools, and operational complexity rather than choosing asyncio simply because it is newer.

Question : How would you investigate high CPU in a Python process?

Capture a profile or sampling stack, inspect hot functions and request/task volume, and compare with recent code or workload changes. Look for accidental busy loops, expensive serialization, inefficient algorithms, excessive logging, or contention. Mitigate first if production impact is severe, then fix and benchmark.
Example : If CPU jumps after a release, first confirm which process and workload are responsible. Capture a profile or sampling stack and check for hot loops, serialization, logging, increased request volume, or an algorithmic regression.
