Question : Explain pointers in C and how they work.
Answer : A pointer is an object whose value represents the address of another object or function. Dereferencing a valid object pointer accesses the pointed-to object, which is why pointers are central to arrays, dynamic allocation, linked structures, callbacks, and low-level interfaces. The important interview point is that pointer validity depends on the lifetime and bounds of the referenced object.
Example : int value=10; int *p=&value; printf("%d",*p); /* dereferencing p reads value */

------------------------------------------------------------------------------

Question : Explain dynamic memory allocation in C.
Answer : Dynamic allocation obtains storage at runtime using functions such as malloc, calloc, and realloc, and releases it with free. The caller must check allocation failure, stay within the allocated bounds, and ensure every owned allocation has a cleanup path. Unlike an automatic local, allocated storage remains valid until it is released or the program terminates.
Example : size_t n=10; int *p=malloc(n*sizeof *p); if(!p)return; p[0]=42; free(p);

------------------------------------------------------------------------------

Question : What is malloc()?
Answer : `malloc` allocates the requested number of bytes of uninitialized storage and returns a suitably aligned pointer or NULL if allocation fails. The caller owns the block and must eventually release it with `free` when it is no longer needed.
Example : int *p=malloc(10*sizeof *p); if(p){p[0]=42; free(p);}

------------------------------------------------------------------------------

Question : What is calloc()?
Answer : `calloc(n, size)` allocates storage for n elements and initializes all allocated bytes to zero. It is convenient for arrays and structures that should start with zeroed bytes, but an all-bits-zero representation is not guaranteed by the C standard to equal every type’s semantic zero value.
Example : int *a=calloc(4,sizeof *a); if(a){printf("%d",a[0]); free(a);}

------------------------------------------------------------------------------

Question : What is free()?
Answer : `free` releases storage previously returned by an allocation function such as malloc, calloc, or realloc. Passing NULL is safe and does nothing. Passing an invalid pointer, freeing the same allocation twice, or accessing the allocation after free results in undefined behavior.
Example : int *p=malloc(sizeof *p); if(p){*p=42; free(p); p=NULL;}

Question : What happens when dynamically allocated memory is not freed?
Answer : If the program loses the pointer to allocated storage without calling free, that storage remains allocated for the lifetime of the allocation and becomes a memory leak. A single short-lived leak may disappear when the process exits, but repeated leaks in a long-running service can grow memory usage and eventually cause failures. The right fix is to establish ownership and cleanup at the point where the resource is acquired.
Example : void f(void){int *p=malloc(1024); if(!p)return; /* use p */ free(p);}

Question : Explain unions in C.
Answer : A union gives multiple members the same storage region, so its size is based on its largest member plus alignment requirements. It is useful when a value can have one of several representations and only one representation needs to be stored at a time. Because the union itself does not record which member is intended, production code commonly pairs it with a tag or enum.
Example : enum Kind{K_INT,K_DOUBLE}; struct Value{enum Kind kind; union{int i;double d;}u;};

Question : Explain functions in C.
Answer : A C function has a return type, parameter list, and body; a declaration exposes its interface while a definition provides the implementation. C passes arguments by value, so pointers are used when a function must modify caller-owned objects or work with dynamically sized data. Keeping functions focused and their ownership contracts clear makes C code easier to test and maintain.
Example : int add(int a,int b); int add(int a,int b){return a+b;}

Question : Explain C preprocessor directives.
Answer : The preprocessor handles directives before the compiler performs normal C translation. It expands macros, includes headers, and selects code with conditional compilation such as #if and #ifdef. Because this stage is largely textual, macros should be used carefully; typed functions and objects are usually safer for ordinary program logic.
Example : #define MAX_USERS 100 #ifdef DEBUG puts("debug"); #endif

Question : Explain static memory allocation.
Answer : Static storage duration means an object exists for the entire execution of the program. File-scope objects and objects declared with static can have static storage duration; a block-scope static also retains its value between calls. The term “static memory allocation” is often used informally, so an interview answer should distinguish storage duration from the physical memory region chosen by the implementation.
Example : static int request_count; void f(void){static int calls; ++calls; ++request_count;}

Question : Write a program to reverse a linked list.
Answer : Reverse a singly linked list by walking it once and redirecting each next pointer. Keep `prev`, `cur`, and `next` so changing `cur->next` does not lose the rest of the list. The iterative solution is O(n) time and O(1) extra space.
Example : Node *prev=NULL,*cur=head; while(cur){Node *next=cur->next; cur->next=prev; prev=cur; cur=next;} head=prev;

Question : Given a sentence and a word, determine whether the word exists in the sentence and return the memory location where it occurs.
Answer : For a substring search, `strstr` returns a pointer to the first matching occurrence inside the original string, or NULL if no match exists. That pointer is a location within the original buffer, so it remains valid only while that buffer is alive and unchanged in ways that invalidate the pointer.
Example : const char *sentence="C makes pointers useful"; const char *p=strstr(sentence,"pointers"); if(p) printf("%s",p);

Question : How can you reach the end of a linked list quickly?
Answer : For a singly linked list without a tail pointer, reaching the end requires following next pointers and is O(n). If the program frequently appends, maintain a tail pointer as part of the list structure; then appending can be O(1) when the tail is valid.
Example : struct List{Node *head,*tail;}; /* tail->next is NULL */

Question : How would you copy a linked list and return a new list?
Answer : A deep copy creates a new node for every source node and reproduces the next links so the new list owns its nodes independently. Do not simply copy the head pointer, because that creates another reference to the same list. Handle allocation failure by cleaning up already-created nodes.
Example : Node *copy=NULL; /* allocate each new node, copy value, and append it; return the new head */

Question : Write a program to delete a node when only a pointer to that node is available.
Answer : If the node is not the last node, copy the next node’s value into the current node and bypass the next node, then free the bypassed node. This does not work for the final node because there is no successor to copy from; a design that owns the previous link is needed for that case.
Example : Node *next=node->next; node->value=next->value; node->next=next->next; free(next);

Question : Reverse a string using pointers.
Answer : Use two pointers, one at the first character and one at the last character before the null terminator. Swap while the pointers have not crossed. The operation is O(n) time and O(1) extra space for a writable character array.
Example : char s[]="hello"; char *a=s,*b=s+strlen(s)-1; while(a<b){char t=*a;*a++=*b;*b--=t;}

Question : Solve a bitmask/bitwise manipulation problem.
Answer : Bitwise operations manipulate individual bits. AND is useful for masking, OR for setting bits, XOR for toggling bits, and shifts for moving a bit pattern. Be explicit about unsigned types when doing bit manipulation so signed-shift behavior does not become an unintended portability issue.
Example : unsigned x=0x2Au; unsigned mask=1u<<3; x|=mask; /* set bit 3 */

Question : Write a Fibonacci program.
Answer : For an iterative Fibonacci implementation, keep the previous two values and update them in a loop. This avoids the exponential repetition of the naive recursive version. Choose an integer type large enough for the expected n and document overflow limits.
Example : unsigned long long a=0,b=1; for(unsigned n=0;n<10;n++){unsigned long long next=a+b; a=b; b=next;}

Example : For insertion after `cur`: `new_node->next=cur->next; cur->next=new_node;` — the old successor is not lost.

Question : Solve an array-operation coding problem.
Answer : First identify whether the operation is search, insertion, deletion, traversal, or transformation. Arrays give O(1) indexed access, but middle insertion/deletion normally requires shifting elements and therefore costs O(n). Check capacity and bounds before modifying the array.
Example : Inserting 9 into `[1,3,5]` at index 1 shifts 3 and 5 right, producing `[1,9,3,5]`.

Question : Explain storage classes and where their variables are mapped.
Answer : Traditional C storage-class specifiers include `auto`, `register`, `static`, and `extern`, but modern explanations are clearer when they separate storage duration, scope, and linkage. For example, a block-scope static has static storage duration, while a file-scope static also has internal linkage. `extern` is mainly about linkage to a definition elsewhere.
Example : static int count; extern int global_value; /* storage/linkage choices should match ownership */

Question : What happens if you declare more variables than the processor has available registers?
Answer : The C language does not promise that a variable declared with or without `register` will occupy a CPU register. The compiler performs register allocation and can keep frequently used values in registers while spilling others to memory when register pressure is high. The number of source variables therefore does not directly determine a fixed hardware limit in portable C.
Example : A loop may keep `i` and an accumulator in registers while less frequently used values are spilled to memory; the compiler decides this.

Question : Explain the memory map/layout of a C program.
Answer : A typical process image is described using code/text, read-only data, writable global/static data, dynamically allocated storage, and stack frames. This is an operating-system/toolchain model rather than a layout guaranteed by the C standard. Exact addresses, growth directions, and segment arrangement vary by platform.

Question : Explain memory allocation strategies such as best fit and worst fit in the context of memory management.
Answer : Best-fit chooses the smallest free block that satisfies an allocation request; worst-fit chooses the largest suitable block. These are allocation-strategy concepts used in memory-management discussions, not guarantees about how a modern C malloc implementation works internally. Compare fragmentation, search cost, and workload before choosing a strategy.
Example : Free blocks: 100, 300, 500 bytes; a 250-byte request could use 300 with best-fit or 500 with worst-fit.

Question : What is the difference between static and dynamic memory?
Answer : Static storage duration applies to objects such as file-scope variables and static locals; their lifetime lasts for the program execution. Dynamic storage is obtained explicitly from allocation functions and lasts until released or until the program ends. Automatic objects have block/function lifetimes and are often associated with stack storage in common implementations.
Example : static int total; int *p=malloc(sizeof *p); /* total has static storage duration; *p has allocated storage duration */

Question : What is a pointer?
Answer : A pointer is an object whose value is used to refer to another object or function. It is not the object itself; it stores a pointer value that can be dereferenced when it points to a live, accessible object. Pointers are central to arrays, dynamic allocation, linked structures, and APIs that modify caller-owned data.
Example : int x=42; int *p=&x; printf("%d",*p);

------------------------------------------------------------------------------

Question : What is a NULL pointer?
Answer : A null pointer has a null pointer value and does not point to a valid object. It is commonly used to represent “no object,” but dereferencing it is undefined behavior. Check a pointer before dereferencing when null is a valid state.
Example : int *p=NULL; if (p) printf("%d", *p);

------------------------------------------------------------------------------

Question : What is a dangling pointer?
Answer : A dangling pointer is a pointer whose referenced object has already ceased to exist or whose allocated storage has been released. The pointer value may still look non-null, but dereferencing it is undefined behavior. The safest approach is to define ownership clearly and invalidate local pointers after free when that helps prevent accidental reuse.
Example : int *p=malloc(sizeof *p); if(p){*p=7; free(p); p=NULL;}

------------------------------------------------------------------------------

Question : What is a wild pointer?
Answer : A wild pointer is an uninitialized pointer whose value is indeterminate. Dereferencing it can access an arbitrary location and cause undefined behavior. Initialize pointers, often to NULL, before using them.
Example : int *p=NULL; /* initialize before deciding what object it should reference */

Question : What is a void pointer?
Answer : void * is the generic object-pointer type in C. It can hold the address of an object of another type and is commonly used by allocation functions and generic APIs. Before dereferencing it, convert it to an appropriate object-pointer type; pointer arithmetic on void * is not defined by standard C.
Example : int x=42; void *vp=&x; printf("%d", *(int *)vp);

------------------------------------------------------------------------------

Question : What is a pointer to a pointer?
Answer : A pointer to a pointer stores the address of another pointer. It is useful when a function must change the caller's pointer, such as updating the head of a linked list. The first * dereference reaches the inner pointer; the second reaches the final object.
Example : int value=10; int *p=&value; int **pp=&p; **pp=20; /* value is now 20 */

Question : What is the difference between an array and a pointer?
Answer : An array is an object containing a fixed number of elements; a pointer is an object that stores an address. They are closely related because an array expression usually converts to a pointer to its first element, but they are not interchangeable: sizeof(array) gives the whole array size, while sizeof(pointer) gives the pointer size.
Example : int a[5]; int *p=a; printf("%zu %zu", sizeof a, sizeof p);

Question : Why does an array name usually decay to a pointer?
Answer : In most expressions, an array expression is converted to a pointer to its first element. This conversion is often called array-to-pointer decay. Important exceptions include operands of sizeof, _Alignof, and unary &, where the array remains an array expression.
Example : int a[3]={10,20,30}; int *p=a; /* p points to a[0] */

Question : What is pointer arithmetic?
Answer : Pointer arithmetic is defined relative to elements of the same array object, including the one-past-the-end position. Adding one to an int * advances by sizeof(int) bytes conceptually, so p+1 points to the next int rather than the next byte. Arithmetic outside the permitted array range is not valid.
Example : int a[3]={10,20,30}; int *p=a; printf("%d", *(p+1)); /* 20 */

Question : What is the difference between *p and &p?
Answer : *p dereferences p and accesses the object p points to. &p produces the address of the pointer variable p itself, so its type is a pointer-to-pointer when p is an object pointer. They answer opposite questions: “what object does p point to?” versus “where is p stored?”
Example : int x=5; int *p=&x; printf("%d", *p); printf("%p", (void *)&p);

Question : Explain const int p, int const p, and const int *const p.
Answer : The position of const matters. `const int *p` means the pointed-to int cannot be modified through p, while `int *const p` means p itself cannot be redirected after initialization. `const int *const p` combines both restrictions. `const int p` and `int const p` are equivalent declarations of a const int.
Example : int x=10,y=20; const int *p=&x; p=&y; /* allowed */ int *const q=&x; *q=11; /* allowed */

Question : What is the difference between malloc(), calloc(), realloc(), and free()?
Answer : `malloc` allocates a requested number of bytes without initializing the contents. `calloc` allocates an array-like block and initializes all allocated bytes to zero. `realloc` resizes an existing allocation and may move it; on failure the original block remains valid. `free` releases allocated storage. C23 also makes `realloc(ptr, 0)` undefined, so use free when the intention is deallocation.
Example : int *p=calloc(4,sizeof *p); int *tmp=realloc(p,8*sizeof *p); if(tmp) p=tmp; else free(p); if(tmp) free(p);

Question : What happens if malloc() fails?
Answer : If an allocation fails, malloc returns NULL. Code should check the result before dereferencing it and then choose an appropriate recovery path: return an error, reduce the request, clean up other resources, or terminate if recovery is impossible. Treating NULL as a valid object pointer leads to undefined behavior.
Example : int *p=malloc(count*sizeof *p); if(!p){fprintf(stderr,"allocation failed\n"); return;}

Question : Why can assigning realloc() directly to the original pointer be dangerous?
Answer : `realloc` changes the size of an existing allocation. It may extend the block in place or allocate a new block, copy the preserved bytes, and release the old block. If it fails for a nonzero size, it returns NULL and the original allocation is still valid, which is why a temporary pointer is safer than assigning directly to the original pointer.
Example : int *tmp=realloc(p,new_count*sizeof *p); if(tmp) p=tmp; else { /* p is still valid */ }

Question : What is a memory leak?
Answer : A memory leak occurs when allocated storage remains allocated but the program has lost the pointer needed to release it. Repeated leaks can increase memory usage and eventually cause allocation failures or system pressure. Prevention comes from clear ownership, cleanup paths, and tools such as AddressSanitizer or leak detectors.
Example : void f(void){int *p=malloc(1024); if(!p)return; /* forgetting free(p) leaks the block */ free(p);}

Question : What is use-after-free?
Answer : After an allocation is freed, every pointer that referred to that storage becomes unusable for accessing that object. Setting one pointer to NULL does not update aliases held elsewhere. Ownership rules and careful lifetime management are required to prevent use-after-free bugs.
Example : int *p=malloc(sizeof *p); int *alias=p; free(p); p=NULL; /* alias is still dangling */

Answer : A mutex provides mutual exclusion: at most one participating thread owns the lock at a time. It is appropriate when multiple threads must safely update shared state or protect an invariant. Correct lock ordering and short critical sections are important for performance and deadlock avoidance.
Example : pthread_mutex_lock(&m); balance+=amount; pthread_mutex_unlock(&m);

Question : What is a semaphore?
Answer : A semaphore is a synchronization primitive with a counter. A counting semaphore can represent available units of a resource, while a binary semaphore can coordinate certain signaling patterns. It differs from a mutex because ownership semantics are different: the thread that waits is not necessarily the one that must release a semaphore.
Example : sem_wait(&slots); /* consume one available slot */ produce(); sem_post(&slots);

Question : Array versus pointer?

Question : What does realloc() do?

Question : Stack versus heap?
Answer : Automatic objects are commonly implemented using stack frames, while dynamically allocated objects are commonly obtained from a heap allocator. The important C distinction is actually storage duration and ownership: automatic objects end with their block, allocated objects end when released. Neither “stack” nor “heap” is a complete guarantee made by the C language.

Question : What does static mean?
Answer : `static` has different effects depending on where it appears. At block scope it gives the object static storage duration; at file scope it gives internal linkage to an object or function. A strong interview answer always states the scope because “static means one thing” is incomplete.

Question : Structure versus union?
